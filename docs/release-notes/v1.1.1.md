## 安装

在飞牛 **应用中心 → 手动上传应用** 中选择对应架构的安装包：

| 文件 | 适用架构 | 确认方式 |
|---|---|---|
| `fn-wireguard-1.1.1-amd64.fpk` | x86_64（Intel / AMD） | `uname -m` 输出 `x86_64` |
| `fn-wireguard-1.1.1-arm64.fpk` | ARM64 | `uname -m` 输出 `aarch64` |

> 系统要求 fnOS ≥ 1.1.3100（低于此版本应用中心会直接拒绝安装）。
> 使用前请在路由器上把用到的 UDP 端口（默认从 51820 起）转发到 NAS 的局域网地址；有多条连接时，每条连接各占一个端口。

从 1.1.0 升级可**直接覆盖安装**：本次不含数据库结构变更（无迁移），连接、设备、账号与设置都不受影响。

## 升级后建议做的一件事

检查「系统设置 → 接入设置 → 对外访问地址」：如果里面写了端口（例如 `home.example.com:51820`），现在只有监听那个端口的那条连接能从外网连回来，其余连接会在「我的连接」里显示「**外网接不回**」。把端口去掉、只留域名或公网 IP，每条连接就会各自用自己的端口；改完给受影响的设备重新生成一次二维码 —— 已经导入到手机里的旧配置不会自动变。

## 更新内容

### 新增功能

1. **对外访问地址可以不写端口**：只填域名或公网 IP 时，每条连接的二维码、邀请与设备配置会自动使用它自己的服务端口（51820、51821…）。路由器上放行哪个端口，就连得回哪条连接 —— 多条连接可以同时从外网接入，不必挤在一个入口上。
2. **「外网接不回」看得见**：写了端口时，系统设置输入框下方会当场列出哪几条连接连不回来；「我的连接」行内标签、新建第 2 条及以后连接时的向导、以及生成二维码的页面都会给出同一句处置 —— 把对外地址里的端口去掉。
3. **体检不再只报「已填写」**：巡检的「对外访问地址」一项，在写死端口且存在监听其它端口的连接时改为「待确认」并点名；不带端口时报通过，并说明每条连接各用自己的端口。

### 修复问题

1. **第二条连接的二维码端口错误**：此前「对外访问地址」被原样写进每一份配置，第二条连接监听 51821 时二维码仍写 51820 —— 握手包落到第一条连接上、公钥对不上，现象只有「怎么都连不上」，状态与日志里都看不出与端口有关。现在地址不带端口时按每条连接各自拼接。
2. **端口提示不再让人查错方向**：此前只有一句话，把「外部端口被另一条连接占用」和「用户自己在路由器上做了换算」混在一起。前者去查路由器只会白找一圈；现在按「有没有连接监听该端口」给出两种不同的处置。

### 其它

1. 新增用例：端口拼接 11 组（域名 / 公网 IP / 裸 IPv6 / 带端口 / 手滑冒号 / 空值）、多连接端口策略与两种提示、巡检两条新结论。
2. 文档：路线图新增「对外地址的端口策略」一节；README 补充「多条连接要不要写端口」的问答。
3. 依赖：无新增。
