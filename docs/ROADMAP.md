## 一、现有能力盘点

### 1.1 功能模块地图

| 模块 | 用户可见能力 | 关键实现 |
|---|---|---|
| 数据面收敛 | 连接启停、设备下发、状态自愈 | `internal/wgback/`（`linux.go` netlink / `mock.go` 内存）、`internal/reconcile/` 10 秒收敛循环 |
| 路由安全 | 不改系统网络、可一键复原 | `routesafety.go` 纯函数铁规则、`policyroute.go` 专用策略表 `51888` + `ip rule` |
| 内网访问 | 设备能访问家里其它机器 | `natplan.go` 决策、`nat.go` 专用 nftables 表 `inet fn-wireguard`、六层自检 |
| 连接管理 | 创建/编辑/启停/导入导出 | `internal/service/interface.go`（跨连接冲突校验、地址端口自动错开） |
| 设备管理 | 二维码、上网方式、期限、配额、批量导入、新建向导 | `internal/service/peer.go`（`ImportPeers` 批量）、`engine.go` 期限与配额强制下线 |
| 密钥托管 | 私钥不落明文、可轮换 | `internal/secretbox/` AES-256-GCM、`wgkey` 密钥生成 |
| 配置生成 | wg-quick 风格配置、二维码 | `internal/wgconf/`、前端二维码渲染 |
| 实时监控 | 流量曲线、设备在线状态 | `internal/api` WebSocket + 前端 `stores/realtime.ts` + ECharts |
| 权限与审计 | 管理员/运维/只读、操作留痕 | `internal/api` 角色校验 + `internal/store` 审计表 |
| 系统维护 | 体检、修复、残留清理、重新应用 | `frontend/src/views/Maintenance.vue` + `internal/service/network.go` |
| 异常可见性 | 顶栏状态栏、全局横幅、行内提示 | `frontend/src/composables/useSystemHealth.ts`（唯一数据源） |
| 帮助系统 | 每个配置项的「是什么/为什么/影响/例子」 | `frontend/src/constants/fields.ts`（`FieldTips` / 配置说明大全） |
| 全局搜索 | 顶栏一个入口搜连接与设备并跳转详情 | `frontend/src/components/GlobalSearch.vue` |
| 备份还原 | 整机配置备份、含/不含密钥 | `internal/service/config.go` + 前端「备份还原」 |
| 交付链路 | 双架构安装包、自动发版 | `scripts/build.sh`、`scripts/version.sh`、`.github/workflows/release.yml` |

### 1.2 已经做扎实的部分

1. **安全边界**：所有网络改动只落在自己创建的对象上，且都有穷举式单元测试（路由安全、内网访问决策、出口网卡选择）。
2. **故障自愈**：收敛引擎幂等 + 启动自愈，配置漂移会自动纠正；单条连接失败不阻断其它连接。
3. **可读的错误**：跨连接冲突、出口网卡探测、内网访问链路都直接给出「哪一层没过 + 怎么处理」。
4. **可追溯的版本**：版本号单一来源，tag 与 manifest 强校验。

### 1.3 已识别的能力缺口（诚实清单）

| # | 缺口 | 现状 | 影响 |
|---|---|---|---|
| 1 | ~~**通知 Webhook 是摆设**~~ **已消除（0.7.0）** | 0.7.0 起四类事件真正推送；界面不再有「暂未生效」标注 | — |
| 2 | ~~无访问控制~~ **已部分消除（0.7.0）** | 已有「设备间隔离」与「按设备划分通行范围」；按设备限制**内网目标**仍靠自定义网段 | 更细粒度的「哪台设备能访问哪个内网服务」仍待做 |
| 3 | 无主机名解析 | 只能下发 DNS 服务器地址，不能把「家里设备名」解析出来 | 用户得记 IP |
| 4 | 对外地址需手工维护 | 公网 IP 变化后要手动改「对外访问地址」并重新分发配置 | 家宽用户高频痛点 |
| 5 | 无历史流量 | 只有实时曲线（WebSocket），不落历史 | 无法回答「这个月谁用了多少」 |
| 6 | 内核不支持时无兜底 | 检测到 `tun_device` 但用户态实现未接入 | 少数老系统的设备装了也用不了 |
| 7 | 账号安全仅有口令 | 无二次验证 | 公网暴露的管理界面风险偏大 |

## 二、下一阶段方向

当前版本已做到「基本可用」：能建连接、发设备、扫码连通、看状态、出问题能定位。**下一阶段不再堆功能，而是围绕三个方向做深**：

| 方向 | 含义 | 判断标准 |
|---|---|---|
| **更好用** | 少点几下、少想几步 | 常见任务的点击次数下降；新增流程有引导；配置项不需要查文档 |
| **更实用** | 覆盖真实使用中「不得不做」的事 | 能在界面内完成，不再需要 SSH 或手工改配置 |
| **体验更优** | 更快、更稳、更清楚 | 异常有原因、操作有反馈、长任务有进度、失败可重试 |

### 优先级判定原则

- **P0**：不做会让用户卡住，或现状与承诺不符（例如摆设设置项）→ 下一版必做
- **P1**：明显提升日常效率或覆盖高频场景 → 排入下一个次要版本
- **P2**：扩大适用范围或加固安全 → 视精力插入
- **P3**：锦上添花、依赖较多 → 放到 1.0 之后

## 三、功能清单（按优先级）

### P0 —— 0.7.0「访问控制与通知」（已完成）

> 主题：让「多人共用」可用，让「出问题第一时间知道」。两者都直接对应 1.3 里的缺口 1、2。
>
> **已完成**，四条验收（V1~V4）逐条落地，实际实现与规划的偏差见[十、0.7.0 偏差补记](#十070-偏差补记)。

#### P0-1 设备间隔离

- **预期目标**：一条连接内可以禁止设备互访，设备只能访问 NAS，不能访问彼此。
- **衔接现有功能**：复用内网访问的专用 nftables 表（`nat.go`）与「只匹配隧道网段」的约束，新增一条 `iifname 隧道 && oifname 隧道 → drop` 的前置规则。
- **依赖**：无（`nat.go` 已具备建表、清理、指纹去抖能力）。
- **验收**：见[八、验收标准](#八验收标准) V1。

#### P0-2 按设备划分访问范围

- **预期目标**：给单个设备指定「只能访问哪些网段」，替代现在「整条连接一刀切」。
- **衔接现有功能**：复用设备的上网方式模型（`route_mode` + `client_allowed_ips`）与 `wgconf` 配置生成；范围校验复用 `routesafety.go` 的网段重叠判定。
- **依赖**：P0-1（两者共用同一套访问控制规则与诊断）。
- **风险提示**：范围改动需要设备重新扫码，界面必须显式提示。
- **验收**：见 V2。

#### P0-3 事件通知（让 Webhook 真正生效）

- **预期目标**：设备上线/离线、连接异常、设备到期、配额用尽等事件推送到用户配置的地址。
- **衔接现有功能**：挂到收敛引擎已有的事件点（`engine.go` 中配额/到期的判定、`Diff` 动作流）；凭据复用 `secretbox`；设置项复用现有的 `notify_webhook` 字段（不再新增字段）。
- **依赖**：无；同时是 0.8「告警与日报」的前置。
- **硬性约束**：**必须异步发送**，绝不能拖慢 10 秒收敛循环。
- **验收**：见 V3。
- **0.7.1 追加（通知能力的收尾）**：
  1. 系统设置新增独立的「事件通知」页签（位于「接入设置」之后），与接入设置各自保存；
  2. 推送格式增加 **Markdown**：钉钉、企业微信与飞书按各自报文结构投递（飞书用交互式卡片，头部按级别上色），并解析响应里的错误码判断业务失败（这类失败原本藏在 HTTP 200 里）；
  3. 事件清单补齐到 **8 类**并按设备/连接/系统分组：新增「连接中断」「连接恢复」「配置下发失败」「残留网络自愈」；
  4. 事件开关的存储语义改为「记录被**明确关闭**的事件」，使以后新增的事件默认开启，避免「新事件静默不生效」；
  5. 界面显示**实际发出的内容**（截断）—— 接收端不显示消息时这是唯一可靠的线索。

#### P0-4 访问控制冲突诊断

- **预期目标**：设备范围、隧道网段、主机网段三者冲突时给出「谁和谁冲突、建议改成什么」，而不是静默失效。
- **衔接现有功能**：复用 0.3.1 的跨连接校验框架与 `useSystemHealth` 的异常清单展示。
- **依赖**：P0-1、P0-2。
- **验收**：见 V4。

### P1 —— 0.8.0「内网体验与管理效率」

#### P1-1 DNS 主机名解析
- **目标**：连进来的设备能用「主机名」访问家里设备。
- **衔接**：NAS 作为隧道内 DNS，只监听隧道地址；下发 DNS 复用现有 `dns` / `dns_mode` 字段。
- **依赖**：P0-3（解析服务异常时需要通知）。
- **难点/风险**：见[七](#七技术难点与风险) R4。

#### P1-2 DDNS 自动更新对外地址
- **目标**：公网 IP 变化后自动更新「对外访问地址」。
- **衔接**：写回现有 `server_endpoint` 设置项；更新结果进入 `useSystemHealth` 异常清单。
- **依赖**：P0-3。
- **风险**：R5。

#### P1-3 设备批量导入与新建向导（已完成）
- **目标**：一次导入多台设备（CSV/文本），新建设备时给分步引导（含「下一步扫码」指引）。
- **衔接**：复用现有导入解析（`/config/import`）与设备创建接口，仅新增批量循环与逐条错误汇总。
- **依赖**：无。
- **验收**：见 V6。
- **实际实现**：批量导入没有复用 `/config/import`（它要求一份含 `[Interface]` 的完整 wg-quick
  文本、且只回传成功总数）。改为新增 `POST /peers/import`：前端把多行文本解析成结构化列表并
  预览，后端逐条创建、**逐条回传成功/失败原因**（重复识别码、格式非法都能定位到具体哪一行）。
  为满足「导入 100 台 ≤ 10 秒」，把落库逻辑从 `CreatePeer` 里抽出为不触发收敛的 `createPeer`，
  批量时最后统一收敛一次（否则 100 台会触发 100 次全量收敛）。新建向导在「添加设备」抽屉内做
  分步（选用途 → 填信息 → 扫码），最后一步**内嵌二维码**，不再跳到另一个弹窗。

#### P1-4 全局搜索与快捷跳转（已完成）
- **目标**：一个入口搜连接与设备，直接跳到对应页面并打开详情。
- **衔接**：纯前端，读已有列表数据。
- **依赖**：无。
- **实际实现**：新增顶栏搜索组件 `components/GlobalSearch.vue`，连接与设备统一检索
  （名称/备注/分组/识别码/所属连接），支持 `Ctrl/⌘ + K` 唤起；数据在首次聚焦时拉取并缓存 30 秒。
  跳转沿用已有的 query 约定并扩展：连接用 `interfaces?edit=<id>`、设备用 `peers?iface=<id>&edit=<id>`，
  目标页监听 query 变化后自动打开对应的详情抽屉（页面已挂载时也能生效）。

### P2 —— 0.9.0「兼容性与账号安全」

#### P2-1 用户态回退
- **目标**：内核无 WireGuard 模块时仍能工作。
- **衔接**：`Backend` 接口已有三个实现（kernel/mock/预留 userspace），新增实现即可；「系统维护 → 运行环境」已展示工作模式。
- **依赖**：无。
- **风险**：R6（体积与行为差异）。

#### P2-2 TOTP 二次验证
- **目标**：管理员账号可开启动态口令登录。
- **衔接**：扩展现有登录流程与用户表；恢复码复用密钥托管。
- **依赖**：无。

#### P2-3 配置快照与一键回滚
- **目标**：关键操作自动留快照，可查看差异并回滚。
- **衔接**：复用现有备份/还原与审计日志；回滚后由收敛引擎保证内核态一致。
- **依赖**：无。
- **风险**：R7。

### P3 —— 1.0.0「正式版」

| 功能 | 目标 | 依赖 |
|---|---|---|
| 历史流量与报表 | 按设备/按天查询流量，配额可视化 | 需新增采样落盘（现在只有实时） |

## 四、依赖关系

```
P0-1 设备间隔离 ──┐
                  ├──> P0-4 冲突诊断 ──> P1-1 DNS 主机名 ──> P3 多机互联模板
P0-2 按设备范围 ──┘

P0-3 事件通知 ────────> P1-2 DDNS ──> P3 计划备份/巡检报告
                 └────> P1-1（解析服务异常告警）

P1-3 批量导入    （独立）
P1-4 全局搜索    （独立）
P2-1 用户态回退  （独立）
P2-2 TOTP        （独立）
P2-3 快照回滚    （独立，但 P3 报表可复用其快照数据）
```

**排期含义**：`P0-3` 是唯一被多个后续功能复用的基础设施，应尽早做且做扎实；`P0-1/P0-2/P0-4` 是一组，必须同版交付（否则诊断说不清）；其余功能互相独立，可按精力插队，不影响主线。

## 五、迭代节奏

| 版本 | 主题 | 节奏 | 完成定义（DoD） |
|---|---|---|---|
| 0.7.0 | 访问控制与通知 | 2~3 周 | **已完成**：功能实现 + 回归用例 + 文档更新 + 版本 bump（真机验证待做） |
| 0.8.0 | 内网体验与管理效率 | 2~3 周 | 同上 |
| 0.9.0 | 兼容性与账号安全 | 2~3 周 | 同上 |
| 1.0.0 | 正式版 | 视前三版收敛情况 | 同上 + 全量回归 + 升级路径验证 |

**每版固定动作**（与[附：发布与分支约定](#附发布与分支约定)配套）：

1. 在 `dev` 上开发，每次可感知改动都 `./scripts/version.sh patch "说明"`；
2. 功能完成 → `gofmt` / `go vet` / `go test ./...` / `vue-tsc` / 前端构建全绿；
3. **真机验证**（对照本版「验收标准」逐条过）；
4. 合入 `main` → 打 tag → 自动出包与 Release；
5. 把本文件对应条目标记为已完成，并补记实际偏差。

> 补丁版本（如 `0.6.1`）用于不发版的小修：修完即出包，不单独合并流程。

## 六、新增功能如何与现有功能衔接

| 新功能 | 挂在哪 | 复用什么 | **不改什么** |
|---|---|---|---|
| 设备间隔离 | `nat.go` 的专用 nftables 表 | 建表/清理/指纹去抖、`PlanNAT` 的纯函数决策模式 | 系统 nftables 表、系统转发策略（继续只在必要时为自己放行） |
| 按设备范围 | `peer` 的 `route_mode` / `client_allowed_ips` | `wgconf` 配置渲染、网段重叠校验 | 现有设备配置格式（保持 wg-quick 兼容） |
| 事件通知 | 收敛引擎事件点 + 设置项 | `secretbox` 存凭据、审计日志记发送结果 | 收敛循环的同步路径（通知异步化） |
| DNS 主机名 | NAT 表 + 设备 `dns` 字段 | 「只匹配隧道网段」的约束 | 系统 DNS 配置、`/etc/resolv.conf` |
| DDNS | `settings.server_endpoint` | 配置修改后的「需重新分发」提示链 | 已有设备配置（不自动改写，只提示） |
| 批量导入 | 现有 `/config/import` | 现有解析与设备创建 | 单条导入行为 |
| 用户态回退 | `Backend` 接口 | 接口契约与安全约束（只操作自己创建的对象） | 内核可用时的默认路径 |
| 快照回滚 | 现有备份/还原 | 审计日志、幂等收敛 | 系统网络（回滚只涉及本应用对象） |

**一条通用约束**：任何新增的网络能力都必须落在「本应用自己的对象 / 自己的表」里，并能一键清理干净；涉及内核规则的改动一律配套穷举回归测试。

## 七、技术难点与风险

| # | 难点 / 风险 | 说明 | 应对 |
|---|---|---|---|
| R1 | ~~同隧道内的隔离规则容易误伤~~ **0.7.0 已规避** | 原计划按 `iifname/oifname` 匹配，写宽了可能连 NAS 自身或回程流量一起丢 | 改为「源与目标都在隧道网段」的地址匹配：NAS 自身走 input、内网回程走放行规则，结构上不可能被命中（见[十](#十070-偏差补记)第 1 条） |
| R2 | 改范围要重新扫码，用户容易漏 | 设备侧 `AllowedIPs` 变更是客户端行为，NAS 无法远程生效 | 保存后弹窗强提示 + 设备列表标记「配置已过期」；提供一键重新生成二维码 |
| R3 | 通知拖慢或拖垮收敛循环 | 收敛循环 10 秒一次，Webhook 目标可能超时 | 通知走独立 goroutine + 队列；单次超时 ≤ 3 秒；同事件 5 分钟去重；失败只记日志不影响收敛 |
| R4 | DNS 接管与系统 DNS 冲突 | NAS 上可能已运行 DNS 服务（Docker 等） | 只绑定隧道内本机地址、只在专用表里做 DNAT；检测到冲突则明确提示而不是抢占 |
| R5 | DDNS 依赖外部服务与凭据 | 各家 API 差异大，凭据泄露风险 | 凭据用 `secretbox` 加密落盘，界面只显示掩码；失败重试并展示最近一次结果 |
| R6 | 用户态回退带来体积与行为差异 | 引入 `wireguard-go` 会显著增大二进制，且性能低于内核 | 仅在检测到内核不可用时启用；界面明确标注「兼容模式」，并提供一键切回 |
| R7 | 快照回滚可能停在半态 | 数据库回滚成功但内核下发失败（或反之） | 回滚后立即触发一次幂等收敛；失败时保留快照并报明确错误，绝不静默 |
| R8 | 历史流量落盘的写放大 | 高频采样会持续写盘，长期可能占满 | 降频采样 + 聚合落盘 + 明确保留策略（默认 90 天），并在维护页显示占用 |
| R9 | **安全边界漂移**（长期风险） | 功能变多后，容易出现「顺手改了系统规则」的回归 | 延续既有三条铁规则 + 每个新 nftables/netlink 能力都必须有穷举测试；CI 强制全量测试 |
| R10 | 不同 fnOS/内核版本行为差异 | nftables 与 netlink 在旧内核上表现不同 | 沿用「多策略探测 + 探测失败必须说清原因」的既有模式，禁止静默失败 |

## 八、验收标准

> 全部为**可衡量**条目；真机验证时逐条勾选。`NAS` 指飞牛 NAS，`设备` 指扫码接入的手机/电脑。

### V1 设备间隔离（P0-1）
- 开启后：设备 A `ping` 设备 B **不通**；设备 A `ping` NAS 隧道地址 **通**。（真机待验证）
- `nft list table inet fn-wireguard` 中新增规则条数 == 预期条数（无多余规则）。
  → 规则对由纯函数 `NATPlan.IsolationRules()` 给出，条数在「系统维护 → 内网访问诊断 → 设备间隔离」直接显示（如「共 3 条阻断规则」），可直接与 `nft` 输出对照。
- 关闭后：表内规则数回到开启前（差值 0），且设备 A 与 B 恢复互通。
  → 关闭时整表按新决策重建（隔离规则消失）；内网访问也关着时整表删除。
- 回归测试覆盖「开启/关闭/切换连接」三种路径。
  → `TestPlanIsolationRulePairs`、`TestPlanIsolationCoversAllTunnels`、`TestPlanIsolationOffChangesNothing`、`TestStateIsolateTracking`。

### V2 按设备范围（P0-2）
- 设备配置里的 `AllowedIPs` 与界面设定**逐字符一致**。
  → 界面设定与配置渲染共用同一套推导（`clientAllowedIPs`），指纹也由同一份输入计算。
- 范围外的目标地址 `ping` 不通，范围内目标 `ping` 通。（真机待验证）
- 修改范围后，界面在设备列表标出「配置已过期」，并可通过一键重新生成二维码消除。
  → 设备列表新增「配置」列，点标签即打开扫码对话框，关闭后标记当场消失（`TestPeerConfigStaleLifecycle`）。
- 保存范围与 NAS 现有网段冲突时，保存被拒绝且提示指出冲突对象。
  → 保存期拒绝两类写法：写成默认路由、与其它连接的隧道网段重叠（`TestPeerScopeConflictRejected`）。

### V3 事件通知（P0-3）
- 四类事件（上线、离线、到期、配额用尽）在 **30 秒内**送达指定地址。
  → 上下线在下一次采样（2 秒）判定后立即入队；离线沿用统一的 3 分钟无握手窗口。
- Webhook 地址不可达时：收敛循环单轮耗时增加 **< 100 ms**（可在运行记录中核对）。
  → 投递走独立队列与 goroutine，`TestNotifyReturnsImmediately` 断言入队耗时 < 100 ms。
- 同一设备同类事件在 **5 分钟内不重复**发送。
  → `TestNotifyDedupeAndFilter`。
- 界面能显示「最近一次发送时间 + 结果」，失败原因可读。
  → 「系统设置 → 事件通知」显示最近一次结果并提供「发送测试通知」；失败同时进入全局异常清单（`TestDeliverFailureIsReadable`）。

### V4 访问控制冲突诊断（P0-4）
- 三类冲突各有一条可读提示，含冲突双方与建议值。实现对应关系：
  ① 设备范围 vs 隧道网段 → `scope_cross_interface`（其它连接）与 `scope_blocked_by_isolation`（本连接的隔离）；
  ② 隧道网段 vs 主机网段 → 沿用内网访问自检的「转发规则」项（`PlanNAT` 的 `SkipReason`）；
  ③ 范围互相矛盾 → `scope_default_route` 与 `scope_needs_lan_access`。
  → 每条结论点名连接与设备（`TestDiagnoseAccessConflicts`）。
- 无冲突时诊断清单显示「全部通过」，不产生误报。
  → `TestDiagnoseAccessNoFalsePositives`（含「停用的连接不参与诊断」）。

### V5 DNS 主机名（P1-1）
- 设备端 `nslookup <主机名>` 返回 NAS 隧道地址。
- NAS 自身 `/etc/resolv.conf` 与上游 DNS **未被修改**（改造前后 diff 为空）。

### V6 批量导入（P1-3）
- 导入 100 台设备耗时 ≤ 10 秒。
- 重复公钥 / 非法公钥被逐条拒绝，并在结果中给出可复制的失败清单。

### V7 用户态回退（P2-1）
- 内核无模块的环境下，设备握手成功、可访问 NAS。
- 「系统维护 → 运行环境」正确显示「兼容模式」。

### V8 TOTP（P2-2）
- 开启后错误动态口令无法登录；恢复码可用；关闭需验证当前口令。
- 原有口令登录路径不被破坏（关闭 TOTP 后行为与升级前一致）。

### V9 快照回滚（P2-3）
- 回滚后连接数/设备数与快照一致；`ip route show default` 与快照时一致。
- 回滚过程中人为中断，下一次收敛能自愈到一致状态（无残留内核对象）。

### V10 流量报表（P3）
- 可查询任意设备最近 7 天按天流量；与实时累计值误差 **< 5%**。
- 维护页显示历史数据占用，并提供清理入口。

## 附：发布与分支约定

- **分支模型**：日常开发一律在 `dev` 分支；新版本定型后合入 `main`，在 `main` 上打 `v*` tag 发版。`main` 只放已定型的版本。
- **每次可感知的改动都升级版本**：只要安装包内容会变，就先 bump 版本再打包，保证设备上装的版本、日志里报的版本、更新说明三者一致。
- **发布载体**：GitHub Release + 双架构 `.fpk` 安装包（`amd64` / `arm64`），由 `git tag v*` 触发 `.github/workflows/release.yml` 自动构建。
- **补丁版本**（`0.6.0 → 0.6.1`）：只修缺陷、不改行为，用户无感升级。
- **次版本**（`0.6 → 0.7`）：新增一组完整功能，界面或行为有可感知变化。

```bash
git checkout dev                 # 日常在 dev 开发
git push origin dev

git checkout main && git merge dev    # 新版本定型后合入
git push origin main
git tag -a v0.7.0 -m "..." && git push origin v0.7.0   # 触发 Release
```

## 九、已发布版本功能规格（摘要）

> 详细说明见各版本 Release 说明与 `apps/fn-wireguard/manifest` 的 changelog。

### 0.3.x —— 安全加固、多连接、异地组网

- 路由安全铁规则：默认不改系统路由；需要下发时写入专用策略路由表 `51888` + `ip rule`，系统主路由表零改动。
- 接口接管保护：不接管、不删除非本应用创建的网卡。
- 连接之间自动错开专用地址与端口，创建前跨连接冲突校验。

### 0.4.0 —— 稳定性与残留治理

- 收敛改为按差异增量下发节点，修复隧道周期性抖动。
- 疑似残留网卡检测与安全清理；自动命名避开内核已存在的网卡名。

### 0.5.x —— 内网访问

- 连接级「允许设备访问家里内网」，专用 nftables 表做源地址改写，只匹配隧道网段。
- 内网访问逐层诊断；出口网卡三重探测（全表扫描 + 内核路由查询 + `/proc`）。

### 0.6.x —— 界面整合与状态可见性

- 独立「系统维护」入口；系统设置只保留改配置类功能。
- 全局异常可见机制：顶栏状态栏、异常横幅、总览状态卡、连接页行内提示（同源判定）。
- 应用图标去除白边；文档重构（README + 本文档）。
- 0.6.1 工具名称统一为「WireGuard 管理工具」。

### 0.7.0 —— 访问控制与事件通知

- **设备间隔离**：连接级开关，禁止设备互访（跨连接一起隔离），设备仍可访问 NAS 与内网。
- **按设备的通行范围**：自定义范围可直接点选探测到的家里网段；保存期拒绝「写成全部流量」与「指向另一条连接」两类写法。
- **配置过期可见**：改动对外地址/DNS/通行范围后，设备列表标出「需重新扫码」，点一下即重新生成并消除标记。
- **事件通知生效**：设备上线/离线/到期/流量用尽推送到 Webhook，支持 JSON/纯文本两种格式与逐事件开关，界面显示最近一次结果并可发送测试通知。
- **访问控制冲突诊断**：范围、开关、隔离三项设置互相矛盾时给出结论、冲突双方与建议（含历史数据兜底）。

### 0.7.1 —— 事件通知收尾

- 系统设置新增独立「事件通知」页签（接入设置 / 事件通知 / 账号管理 / 备份还原 / 关于），通知配置与接入配置各自保存。
- 推送格式支持 **Markdown**：钉钉、企业微信、飞书群机器人按各自报文结构投递（飞书发交互式卡片，异常红色头部、正常绿色头部）；响应里的错误码非 0 视为失败并给出原因（`errcode` 对所有格式检查，飞书的 `code` 仅在确认是飞书时检查，避免把通用接收端的 `code=200` 误判为失败）。
- 可配置事件补齐到 **8 类**并分组：设备（上线/离线/到期/流量用尽）、连接（中断/恢复）、系统（配置下发失败、残留网络自愈）。
- 事件开关改为「记录被明确关闭的事件」：以后新增的事件默认开启，不再出现「新事件静默不生效」。
- 「最近一次」记录里可展开查看**实际发出的内容**，接收端不显示消息时可直接对照排查。

## 十、0.7.0 偏差补记

> 按「每版固定动作」第 5 条记录实际实现与规划的差异，便于后续版本估工时不再踩同样的坑。

| # | 原规划 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | P0-1 用 `iifname 隧道 && oifname 隧道 → drop` | 改为「源与目标**都**落在隧道网段 → drop」 | 地址匹配精确等价于「设备之间互访」：访问 NAS 走 input 路径、访问内网走放行规则，都不会命中。不需要猜接口名，R1 担心的「误伤 NAS 自身与回程流量」从根上消失，也无需额外放行。代价是设备侧表现为超时而非立即拒绝 —— 用 drop 是为兼容旧内核（转发路径上生成 ICMP 依赖 conntrack 与内核版本） |
| 2 | P0-3「设置项不再新增字段」 | 新增 `notify_events`（逐事件开关）与 `notify_format`（JSON/纯文本） | 「配了就全推」在设备多时会被上线消息淹没；纯文本是自建推送服务（ntfy 等）的硬需求。`notify_webhook` 本身仍复用旧字段 |
| 3 | P0-2「给单个设备指定只能访问哪些网段」 | 复用既有 `route_mode=custom` + 新增配置指纹与保存期冲突校验 | 该模型 0.5 起已存在，真正缺的是「改完要重新扫码」的可见性与保存期的拦截 |
| 4 | P0-4 三类冲突 | 实际四类（多一类「隔离与通行范围互相抵消」） | 这是两项新功能组合后最容易踩的坑，且现象完全不可见（设备之间就是不通） |
| 5 | V3 要求「连接异常」也推送 | 0.7.0 未做；**0.7.1 已补上**（「连接中断 / 恢复」，并一并补齐「配置下发失败」与「残留网络自愈」） | 0.7.0 当时判断与设备上下线重合、且已被全局异常清单覆盖；但「不主动打开界面就发现不了」才是通知的真正价值，故补做 |

顺带完成的两处清理：

- 上下线判定的 3 分钟阈值此前在收敛引擎与状态缓存里各写一遍，现统一为 `model.OnlineWindow`；
- 通知地址一律脱敏展示与记日志（令牌常带在 URL 路径里），失败原因也不回显完整地址。
