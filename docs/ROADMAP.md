# fn-WireGuard 版本规划与功能规格

> 本文是项目的**演进路线图与功能规格说明**，面向使用者和贡献者。
> 版本号遵循语义化（`主.次.补丁`），其中「补丁」用于缺陷修复、「次」用于新增功能。
> 版本号的唯一事实来源是 `apps/fn-wireguard/manifest` 的 `version` 字段。

## 一、版本规划概述

### 1.1 发布节奏与约定

- **每次可感知的改动都升级版本**：只要安装包内容会变，就先 bump 版本再打包，保证设备上装的版本、日志里报的版本、更新说明三者一致。
- **发布载体**：GitHub Release + 双架构 `.fpk` 安装包（`amd64` / `arm64`），由 `git tag v*` 触发 `.github/workflows/release.yml` 自动构建。
- **补丁版本**（`0.5.2 → 0.5.3`）：只修缺陷、不改行为，用户无感升级。
- **次版本**（`0.5 → 0.6`）：新增一组完整功能，界面或行为有可感知变化。

### 1.2 演进主线

项目从「把 WireGuard 搬进飞牛 NAS 的图形界面」出发，一路沿着三条主线演进：

1. **可用性**：让不懂网络的用户也能三步上手（一键创建、扫码连接、白话配置说明）。
2. **安全性**：守住「绝不破坏 NAS 系统网络」这条铁规则，所有网络改动都限定在本应用自己的对象内，可回退、可清理。
3. **可观测性**：把「连不上 / 访问不了」这类只有现象、没有原因的问题，逐层拆开、直接告诉用户卡在哪一层（内网访问诊断、系统状态栏、异常横幅）。

后续版本继续围绕这三条主线推进，直到 1.0 达到「普通用户可放心长期使用、运维场景有完整工具箱」的目标。

### 1.3 路线图总览

| 版本 | 主题 | 状态 |
|---|---|---|
| 0.3.x | 安全加固 / 多连接 / 异地组网 | ✅ 已发布 |
| 0.4.0 | 稳定性与残留治理 | ✅ 已发布 |
| 0.5.x | 内网访问（设备访问家里其它设备） | ✅ 已发布 |
| 0.6.0 | 界面整合与状态可见性 | ✅ 已发布 |

## 二、已发布版本功能规格（摘要）

> 详细说明见各版本 Release 说明与 `apps/fn-wireguard/manifest` 的 changelog。

### 0.3.x —— 安全加固、多连接、异地组网

- 路由安全铁规则：默认不改系统路由；需要下发时写入专用策略路由表（`table 51888`）+ `ip rule`，系统主路由表零改动。
- 接口接管保护：不接管、不删除非本应用创建的网卡。
- 连接之间自动错开专用地址与端口（`wg0 → 10.10.0.1/24 + 51820`，`wg1 → 10.11.0.1/24 + 51821`），创建前跨连接冲突校验。
- 异地组网：NAS 主动访问对端内网，且不碰系统路由。

### 0.4.0 —— 稳定性与残留治理

- 收敛改为按差异增量下发节点，修复隧道周期性抖动。
- 缓存对端地址解析；疑似残留网卡检测与安全清理；自动命名避开内核已存在的网卡名。

### 0.5.x —— 内网访问

- 连接级「允许设备访问家里内网」开关（默认开），由 NAS 对隧道网段做 SNAT。
- 规则写在应用自己的 nftables 表，只匹配隧道网段，不动系统表；关闭/卸载整表删除。
- 内网访问逐层诊断：开关 / 设备通行范围 / 转发规则 / 内核转发 / 系统转发链 / 出口网卡。
- 出口网卡探测：读全部路由表 + 内核路由查询 + `/proc` 三重兜底，WireGuard 网卡一律不作为出口。

### 0.6.0 —— 界面整合与状态可见性（当前）

见 [0.6.0 功能规格](#060-功能规格)。

## 三、规划中的版本功能规格

### 0.7.0 —— 访问控制

**目标**：从「一条连接里所有设备都能互相访问」细化到「谁可以访问谁」，满足多人共用、临时授权、设备分级等真实家庭/小团队场景。

| 特性 | 功能说明 | 验收要点 |
|---|---|---|
| 设备间隔离 | 连接级开关「设备之间禁止互通」，开启后同一连接内的设备只能访问 NAS，不能互相访问 | 规则写入专用 nftables 表；只匹配隧道网段；关闭后整表删除 |
| 按设备划分访问范围 | 给单个设备指定允许访问的内网网段（替代现在全连接的「全部内网」） | 与现有「设备通行范围」合并成统一模型；设备侧配置正确生成 `AllowedIPs` |
| 规则冲突诊断 | 当设备范围、隧道网段、主机网段三者重叠时，给出可读提示而不是静默失败 | 复用现有跨连接校验框架；诊断条目能指出冲突双方与建议值 |
| 访问控制默认值 | 保持「开箱即用」：默认全互通，只有用户主动开启隔离才生效 | 升级不影响已有连接行为 |

### 0.8.0 —— 内网体验

**目标**：把「外网连回家」这条最主流的链路做到更好用、更可靠。

| 特性 | 功能说明 | 验收要点 |
|---|---|---|
| DNS 主机接管 | 允许把 NAS 作为内网 DNS，连进来的设备能用「主机名」访问家里设备（而非 IP） | 只对隧道网段下发 DNS；不与系统 DNS 服务冲突 |
| DDNS 自动更新 | 接入常用 DDNS 服务，自动更新「对外访问地址」，避免公网 IP 变动后连不上 | 更新失败在「系统状态」可见；支持占位符回退到手动地址 |
| 告警 Webhook | 连接异常、设备上线/下线、配额超限时推送到用户指定的地址 | 事件分类可配；失败静默重试并显示最近一次结果 |

### 0.9.0 —— 兼容性与安全增强

**目标**：扩大可运行范围、加固账号安全。

| 特性 | 功能说明 | 验收要点 |
|---|---|---|
| 用户态回退 | 内核无 WireGuard 模块时自动降级为 userspace 实现 | 自动检测、无感切换；工作模式在「系统维护 → 运行环境」可见 |
| TOTP 二次验证 | 管理员账号可开启 TOTP，登录需额外输入动态口令 | 兼容标准 TOTP App；提供恢复码兜底 |
| 密钥托管优化 | 私钥/口令加密方式与备份策略梳理 | 密钥仍只存本机；导出/备份可明确选择是否含密钥 |

### 1.0.0 —— 正式版

**目标**：达到「长期稳定使用」的完成度，具备完整的运维工具箱。

| 特性 | 功能说明 | 验收要点 |
|---|---|---|
| 配置快照对比与回滚 | 关键操作自动留快照，可查看差异并一键回滚 | 快照含连接/设备/设置；回滚不影响系统网络 |
| 多 NAS 互联模板 | 内置「两处网络互联」的向导模板，降低异地组网门槛 | 复用策略路由表机制；主路由表零改动 |
| 流量报表 | 按设备/按时间维度的流量统计与配额 | 复用现有实时流量采集；数据落盘可查 |

## 四、0.6.0 功能规格

本次（0.6.0）聚焦两件事：**把维护类功能从「设置」里拆出来独立成页**，以及**让异常状态在任意页面都能被即时感知**。

### 4.1 界面整合：系统设置与系统维护分离

**设计原则**：`系统设置 = 改配置`，`系统维护 = 看健康、修问题`。两者职责不再混杂。

- 新增独立菜单 **「系统维护」**，统一承载：一键体检、异常清单、NAS 系统网络修复、内网访问诊断、疑似残留网卡清理、重新应用全部配置、运行环境。
- **「系统设置」** 只保留：接入设置、账号管理、备份还原、关于（并在「关于」标注「系统状态与修复请到系统维护」）。
- **操作路径优化**：需要修复的问题只出现在一处（维护页的「待处理事项」），并在其它页面以「去处理」按钮直达，用户不用在多个页面之间找入口。

### 4.2 异常状态展示机制

**设计原则**：一份数据、多处展示。异常判定集中在 `useSystemHealth`（前端唯一数据源），顶栏、横幅、总览、连接页、维护页读同一份清单，口径一致，杜绝「总览报红、连接页显示正常」的自相矛盾。

- **数据来源**：`/system/network`（网络自检）、`/health`（组件健康）、`/overview`（连接状态），每 60 秒轮询，任一接口失败不影响其它。
- **异常清单**（按重要性排序）：后台服务未运行 → 标准模式不可用 → NAS 上网路线异常 → 已启用但未工作的连接 → 内网访问已开启但未生效 → 疑似残留网卡 → 未填对外访问地址。
- **三处展示**：
  1. **顶栏状态栏**：红/黄/绿圆点 + 文字（「N 项异常 / N 项待确认 / 系统正常」），任何页面可见，点击直达维护页。
  2. **全局异常横幅**：存在「功能确实没在工作」的问题（error 级）时，横幅固定在内容区上方，随页面滚动而保持可见，含「立即修复 / 去处理」。
  3. **总览页系统状态卡 + 连接页行内提示**：总览给完整清单；连接页在「已启用但未工作」「内网访问已开启但未生效」的连接上直接标黄。
- **分级**：`error`（功能确实没工作，红色、进横幅）与 `warning`（待确认，黄色、只进状态栏与清单）。
