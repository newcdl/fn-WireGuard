# 界面截图

主 [README](../../README.md) 的「界面预览」一节引用这里的图片。**文件名必须与下表一致** ——
README 里写的就是这些名字，改名字要同时改 README。

现有六张都取自 `dev` 分支的**内置演示模式**（`./scripts/dev.sh`，内存后端）：
数据是示例数据，界面顶栏带着「演示模式」标记，这是刻意的 —— 不拿真实环境的截图冒充，
同时避免把真实公网地址、域名、设备名与二维码带进公开仓库。

## 重新生成

```bash
./scripts/dev.sh                      # 起演示实例（默认 127.0.0.1:18080，账号 admin / admin12345）
```

造一份像样的演示数据（否则截图里是空态），再逐页截取。要点：

- **页面地址是 hash 路由**：`http://127.0.0.1:18080/#/peers`，不是 `/#peers`；
  写成 `/peers` 会被重定向回总览，截出来全是同一页。
- **造数据用接口**：`PUT /api/v1/settings` 里把 `server_endpoint` 设成示例域名（如 `nas.example.com`），
  再用 `POST /api/v1/interfaces` 与 `POST /api/v1/peers` 建几条连接与设备。
  演示模式会自动为设备造出握手时间与流量，所以总览的曲线与「在线」状态都是活的。
- **连接名是内核网卡名**：只允许小写字母、数字、短横线、下划线（`wg0`、`home`、`office`），
  中文名会被拒绝 —— 这是内核接口的约束，不是文案问题。
- **不要用 `PATCH /api/v1/interfaces/{id}` 做局部更新**：其中 `enabled`、`autostart` 这类布尔字段没有
  「保持原值」语义，漏传就会把它们置为 false（编辑抽屉总是提交完整对象，所以界面不受影响）。

## 拍摄约定

- **尺寸**：桌面端视口取 1280×820；表格列较多、容易被固定操作列压住的页面用 1440 宽。
  导出后统一缩到 **1440px 宽**存放 —— 六张图同宽同比例，README 里并排两列才齐。
- **格式**：PNG，单张控制在 300KB 以内（可用 `sips --resampleWidth 1440` 缩放，纯色区块多，通常压得很小）。
- **深浅一致**：同一批截图要么全浅色、要么全深色，只有 `dark.png` 例外。
- **不含真实数据**：**不要出现真实的公网 IP、DDNS 域名、WireGuard 公钥与二维码** ——
  二维码里就是配置本身，而截图会随仓库长期公开。演示数据里的域名一律用 `example.com` 这类占位值。
- **不加设备边框与阴影**：README 里是并排两列，自带边框会让两列看起来不齐。

## 商店上架材料

飞牛应用中心的截图**不在 manifest 里** —— 官方字段清单（20 个）中没有截图 / 预览图字段，应用包目录里也没有对应约定；
截图属于**提交上架时的材料**。官方「上架应用」章节列的材料是：① 由 fnpack 生成的 `.fpk`
② 应用图标 ③ 截图，并要求「截图应展示真实应用界面和核心流程，不应使用占位页面或开发阶段的临时设计图」——
本目录这六张正好符合，可直接作为提交材料。

图标是另一套（`apps/fn-wireguard/ICON.PNG` 64×64 与 `ICON_256.PNG` 256×256，fnpack 会检查存在性），
别与 `app/ui/images/` 下的入口图标混为一谈。

### 能不能让截图直接出现在应用中心的介绍里

`desc` 的官方口径是「必要时可以使用 HTML 内容」，但有三条约束让它不适合放图：

1. **必须是单行**：manifest 是逐行键值，真正的换行会破坏解析；即使用 `<br>`，也依赖 HTML 被渲染这一前提。
2. **渲染范围没有承诺**：官方没有说明白名单标签、是否允许外链图片，文档反而提醒不要假设可以嵌入远程资源。
   若实际不渲染或只做转义，商店门面上会直接露出一串标签文本。
3. **国内网络取不到图**：图片若托管在 `raw.githubusercontent.com`，国内经常连不上，用户看到的是裂图 ——
   对商店门面来说，裂图比没有图更糟。

因此当前 `desc` 采用**纯文本亮点结构**（一句话定位 → 三步上手 → 亮点功能 → 账号安全 → 可靠与可回溯 → 不改系统网络），
不放图。若日后在开发者后台或真机商店里实测确认图片能正常渲染（且换了国内可访问的图床），
把下面这段**追加到 `desc` 末尾**即可 —— 放末尾是为了万一不被渲染，前面的文字依然完整可读：

```html
<span style="display:block"><img src="https://raw.githubusercontent.com/newcdl/fn-WireGuard/dev/docs/screenshots/overview.png" width="480"><br><img src="https://raw.githubusercontent.com/newcdl/fn-WireGuard/dev/docs/screenshots/peers.png" width="480"></span>
```

> 若更希望在**应用内部**展示截图（完全在我们控制范围内、不依赖商店渲染），可以把图片放进安装包并在
> 「系统设置 → 关于」加一个截图折叠区 —— 代价是包体增大（六张合计约 1.1MB）。需要时再说。

## 应用介绍（`desc`）的格式

- **必须是单行**：manifest 是逐行键值，版本脚本与打包工具都按行读，真正的换行会破坏解析 ——
  所以 `desc` 里不能出现真换行，想分层只能靠标点与 HTML 标记。
- **换行用 `<br>` 表达**：官方对 `desc` 的说明是「必要时可以使用 HTML 内容」，因此逐行亮点用 `<br>` 分隔。
  万一某天发现应用中心把 `<br>` 当文字显示，把 `<br>` 全部换成全角分号即可，其余文字一字不用动。
- 当前结构：一句话定位 + 八条亮点（三步上手 / 访问控制 / 内网域名 / 账号安全 / 可靠可回溯 /
  事件通知 / 内置体检 / 不碰系统网络），约 480 字。
- 改完 `desc` 后跑一次 `./scripts/build.sh all`：fnpack 会重新解析 manifest，写坏了当场就能发现。
