## 这是什么

飞牛的远程访问（FN Connect）带宽有限且只转发 5666 端口，想要稳定、安全、全端口访问自己家的 NAS，WireGuard 是最靠谱的方案。但传统做法要 SSH 进系统、手写 `wg0.conf`、自己算密钥、再想办法把配置发给手机 —— 对不熟悉网络的用户门槛很高。

**fn-WireGuard 把这一整套搬到网页上**：以 `.fpk` 安装到飞牛应用中心，打开就是图形界面，建一条连接、加一台设备、扫个二维码，手机就连回家了；NAS 重启后配置自动恢复，不需要任何手工操作。

适用场景：

| 场景 | 效果 |
|---|---|
| 手机 / 笔记本在外访问家里的 NAS 与内网设备 | 只让访问家里的流量走隧道，上网速度不受影响 |
| 在公共 WiFi 下上网更安全 | 全部流量经家里出口，公共网络看不到你的访问内容 |
| 两处办公地点 / 两台 NAS 互联 | 双方内网设备像在同一局域网内互相访问 |
| 给临时人员发放限时访问权限 | 设定到期时间或流量上限，到点自动失效 |

## 核心特性

### 连接与设备管理

- 连接的创建 / 编辑 / 删除 / 启停，地址、端口、MTU、DNS 全字段可视化配置
- 设备（Peer）的添加 / 编辑 / 删除 / 启停，支持多选批量启用、停用、延期、设置心跳与流量上限
- 自动分配内部地址、自动生成密钥与二次加密口令，一键产出**配置文件 + 二维码**
- 设备分组标签、备注、到期时间、流量配额，超限自动停用并记录原因

### 新手友好

- **场景预设**：不说参数，只问目的。选「只访问家里设备」即自动填好全部参数，并直接告诉你预期效果
- **逐项说明**：每个字段旁边一个 ⓘ，点开是「它是什么 / 什么时候需要改 / 改完会怎样 / 可以参考这样填」
- **配置说明大全**：侧栏一键打开，按模块列出全部说明
- **三步引导**：全新安装时总览页出现上手引导，可「一键创建推荐连接」

### 可观测

- 实时吞吐曲线、设备在线状态、最近握手时间、累计收发流量
- 运行日志与操作记录（谁在什么时候改了什么），操作记录带**哈希链防篡改校验**

### 可靠

- 声明式配置 + 收敛引擎：数据库是唯一事实来源，每 10 秒对齐一次内核实际状态，人工误改会被自动纠正
- **重启自恢复**：开机后自动重建连接、地址与设备，无需重放任何脚本
- 配置导入 / 导出（兼容 `wg-quick` 语法）、备份与一键还原

### 适配

- 手机、平板、桌面全尺寸自适应：移动端为底部导航 + 卡片列表 + 全屏表单
- 以 iframe 形式嵌入飞牛桌面，深浅色主题跟随系统

## 安全承诺（铁规则）

> 这一节是本项目最看重的部分。NAS 是家里的网络中枢，**一个管理工具绝不该把主人锁在门外**。

早期版本曾因把「服务端准入地址」与「客户端上网方式」混用同一字段，在用户填入 `0.0.0.0/0` 时向主机写入了一条默认路由，抢占系统默认路由，导致 **FN Connect、应用市场、系统更新全部断网**。该问题已在 0.3.0 彻底修复（`0.2.0` 及更早版本请勿使用）。

现在的实现把下面几条写成了**代码级约束**，并由专门的回归测试守护：

| # | 铁规则 | 实现方式 |
|---|---|---|
| 1 | **绝不创建、修改或删除系统默认路由** | 路由决策纯函数 `PlanRoutes()` 中，前缀长度为 0 的网段一律拒绝 |
| 2 | **绝不覆盖系统上已存在的任何路由** | 只使用 `RouteAdd`（已存在即失败跳过），对齐 `wg-quick` 的安全语义；不使用 `RouteReplace` |
| 3 | **默认不管理本机路由** | `route_table` 默认 `off`；只有显式选择「客户端模式」才可能下发路由 |
| 4 | **与主机网段重叠的路由一律跳过** | 收集全部网卡网段与既有路由做包含关系比对 |
| 5 | **只操作自己创建的对象** | 受管名单记录在 `netstate.json`；同名网卡若非本应用创建，**拒绝接管**而非强行改写 |
| 6 | **启动即自愈** | 每次下发前扫描「指向本应用网卡的默认路由」并删除；若系统因此失去默认路由，按启动基线恢复 |
| 7 | **停用与卸载即清理** | 停止应用或卸载时主动删除自己创建的网卡与残留路由，不留痕迹 |
| 8 | **历史危险配置自动转换** | 升级时自动把 `0.0.0.0/0` 从准入地址移除并转成「设备上网方式」，写入运行日志告知用户 |

另外，本应用**不修改 DNS、不修改防火墙、不修改任何内核参数**，也没有任何 shell 调用（全部走 netlink 系统调用），不存在命令注入面。

界面内建**「NAS 系统网络安全检查」**（系统设置 → 运行状态，以及总览页自动检测）：随时确认本应用有没有影响 NAS 自身的上网路线，发现问题可一键修复。

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 数据面 | `wgctrl` + `netlink` | 走 generic netlink 直连内核，**不调用 `wg` / `wg-quick` 命令**，无 `wireguard-tools` 依赖 |
| 后端 | Go 1.24 | 单二进制、`CGO_ENABLED=0`、零运行时依赖，可静态交叉编译 amd64 / arm64 |
| 存储 | `modernc.org/sqlite` | 纯 Go 实现，无 cgo，单文件数据库 |
| Web | `chi` + `gorilla/websocket` | REST API 与实时状态推送 |
| 前端 | Vue 3 + TypeScript + Vite | 构建产物由 `go:embed` 内嵌进后端二进制，fpk 不依赖 Node |
| UI | Element Plus + ECharts | 定制主题，深浅色自适应，移动端适配 |
| 加密 | AES-256-GCM + argon2id | 私钥 / 口令落库即密文；登录口令用 argon2id 哈希 |

**为什么是 Go**：WireGuard 管理是系统级 netlink 操作，Go 能提供「零依赖 + 原生系统调用 + 双架构静态编译 + 内嵌前端」的组合，是 fpk 形态下最省心的选择。

## 架构

```
┌──────────────────────────────────────────────────────────┐
│ 飞牛桌面  →  以 iframe 嵌入  http://<NAS>:34567/           │
└───────────────────────┬──────────────────────────────────┘
                        │ HTTP / WebSocket
┌───────────────────────▼──────────────────────────────────┐
│ fnwg-web   （无特权，以用户 fnwg 运行）                    │
│  · 页面托管 · REST API · 登录与权限 · 实时推送              │
└───────────────────────┬──────────────────────────────────┘
                        │ Unix Domain Socket（0600，方法白名单）
┌───────────────────────▼──────────────────────────────────┐
│ fnwg-agent （root，systemd 加固 + 最小能力集）             │
│  · netlink 幂等收敛 · 状态采集(2s) · 路由安全护栏 · 自愈     │
└───────────────────────┬──────────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────────┐
│ 内核 wireguard 模块 · 路由表                              │
│ 数据：/vol*/@appdata/fn-wireguard/{fnwg.db, master.key}    │
└──────────────────────────────────────────────────────────┘
```

**为什么拆成两个进程**：管理 WireGuard 必须拥有 `CAP_NET_ADMIN`，但 Web 面（监听端口、处理请求）是最容易被攻击的部分。把 root 能力收敛到一个**不监听任何 TCP 端口**、只通过本地 socket 通信的 agent，Web 层以普通用户运行，形成纵深防御。

agent 仅接受白名单方法调用（`reconcile` / `status` / `health` / `iface.delete` / `net.inspect` / `net.repair` / `net.cleanup`），**协议层就不提供任何「修改系统路由」的能力**。systemd 单元把能力集限制为 `CAP_NET_ADMIN CAP_NET_RAW CAP_CHOWN CAP_DAC_OVERRIDE CAP_FOWNER`，并开启 `NoNewPrivileges`、`ProtectSystem=full`。

## 快速开始

### 环境要求

| 组件 | 版本 | 用途 |
|---|---|---|
| Go | 1.24+ | 编译后端 |
| Node.js | 20+ | 构建前端 |
| fnpack | 1.2.x | 打包 `.fpk`（[官方下载](https://developer.fnnas.com/docs/cli/fnpack/)） |

### 克隆与编译

```bash
git clone https://github.com/newcdl/fn-WireGuard.git
cd fn-WireGuard

# 只编译（前端未构建时使用占位页面，可直接跑通 go build / go test）
go build ./... && go test ./...

# 完整构建：前端 → 内嵌 → 交叉编译 → 打包
./scripts/build.sh amd64      # 只出 x86_64 包
./scripts/build.sh arm64      # 只出 ARM 包
./scripts/build.sh all        # 两个架构都出
./scripts/build.sh            # 只编译当前架构，不打包
```

产物位于 `dist/`：

```
dist/fn-wireguard-0.3.0-amd64.fpk
dist/fn-wireguard-0.3.0-arm64.fpk
```

> 前端产物由 `go:embed` 内嵌，通过构建标签 `embedui` 控制：日常开发与单元测试走占位实现（仓库不跟踪构建产物），发布构建由 `scripts/build.sh` 自动加上该标签。

### 本地开发（不会碰你的真实网络）

```bash
./scripts/dev.sh              # 启动开发服务 http://127.0.0.1:18080
                              # 使用内存后端，不创建任何网卡、不改任何路由
./scripts/dev.sh frontend     # 前端热更新（Vite 开发服务器，自动代理到后端）
```

开发模式默认账号 `admin` / `admin12345`（仅开发模式自动创建，生产环境走首次初始化页）。

## 安装到飞牛 NAS

1. 在 NAS 上确认架构：`uname -m` → `x86_64` 用 amd64 包，`aarch64` 用 arm64 包
2. 飞牛 **应用中心 → 手动上传应用 → 选择对应 `.fpk`**
3. 安装向导里填写「服务端对外地址」（公网域名或 IP，可留空稍后配置）
4. 安装完成后，桌面出现「WireGuard 管理」图标，在窗口内即可完成全部配置

**使用前请在路由器上将 WireGuard 端口（默认 UDP 51820）转发到 NAS 的局域网地址**，否则外网设备无法连入；管理端口 34567 仅供局域网访问，**不要暴露到公网**。

卸载时数据目录默认保留，重新安装即自动恢复配置。

## 三步上手

1. 打开「WireGuard 管理」→ 首次进入设置管理员账号密码
2. **总览页点「一键创建推荐连接」**（或到「我的连接」新建，选一个场景预设）
3. 到「我的设备」添加设备 → 选「只访问家里设备」→ 填个名字 → 创建后直接弹出二维码 → 手机安装 WireGuard 官方 App 扫码即可连回家

需要在外网使用时，再到 **系统设置 → 接入设置** 填写「对外访问地址」，然后重新生成该设备的二维码。

## 配置项白话对照表

| 界面名称 | 对应技术概念 | 一句话说明 |
|---|---|---|
| 我的连接 | WireGuard Interface | 一条安全通道，相当于给远程设备开的一扇门 |
| 我的设备 | Peer / 对等节点 | 允许接入的手机、电脑等 |
| 连接名称 | Interface Name | 通道的名字，保持默认 `wg0` 即可 |
| 服务端口 | Listen Port | 外部设备连进来的入口，默认 51820 |
| 本机专用地址 | Interface Address | NAS 在通道内部的「内线号码」，默认 `10.10.0.1/24` |
| 数据包大小上限 | MTU | 默认 1420；能连上但打不开网页时调到 1380 或 1280 |
| 域名解析服务器 | DNS | 上网的「查号台」，例如 223.5.5.5 |
| 域名解析方式 | DNS Mode | 只下发给设备（推荐）/ NAS 也一起使用 / 不参与 |
| 本机访问路线管理 | Route Table | **默认「不管理」**，本应用绝不改动 NAS 自身路由 |
| 分配给这台设备的内部地址 | Peer AllowedIPs | 设备的门牌号，一般留空自动分配 |
| 设备上网方式 | Client-side AllowedIPs | 设备的哪些流量走隧道：全部 / 仅访问家里 / 自定义 |
| 保持连接心跳 | PersistentKeepalive | 默认 25 秒，让手机在移动网络下保持在线 |
| 二次加密口令 | Preshared Key | 在标准加密之上再加一道密码 |
| 对方设备识别码 | Peer Public Key | 对方设备的公开身份标识，可安全分享 |
| 对接固定服务器 | Endpoint | 对方有固定公网地址时填写，一般留空 |
| 使用期限 | Expire At | 到期自动停用，适合给临时人员发权限 |

## 数据与隐私

- 全部配置、密钥、日志均保存在 **NAS 本机**数据目录 `@appdata/fn-wireguard`，不会上传到任何第三方服务器
- 私钥与二次加密口令在落盘前使用 **AES-256-GCM** 加密，主密钥仅保存在本机并限定属组可读
- 登录口令使用 **argon2id** 哈希，不可逆
- 不采集、不外传任何个人数据；只有你主动配置告警 Webhook 时才会向你指定的地址发送通知
- 配置导出与备份文件默认存放在 `@appdata/fn-wireguard` 下，可自行取走；备份可选择是否包含密钥

## 常见问题

### Q1. 装完之后 NAS 自身上不了网了（FN Connect 失效、应用市场打不开）怎么办？

**先执行这几条命令**（需要 root 或 sudo），它们只会删除本应用自己创建的残留对象：

```bash
ip route show default                 # 1. 先看现象：是否多了一条 default dev wg0
sudo ip route del default dev wg0     # 2. 删除被抢占的默认路由
sudo ip link del wg0                  # 3. 删除残留网卡（连带其路由一起消失）
ip route get 1.1.1.1                  # 4. 验证：应显示走 end0/eth0 等主网卡
```

系统原本的默认路由（`default via 192.168.3.1 dev end0 ...`）并没有被删除，所以**无需手工加回任何路由**。

也可以直接 `sudo fnwg-cli cleanup`，效果相同。

> 该问题仅存在于 **0.2.0 及更早版本**。0.3.0 已从代码层面禁止此类行为，并在启动时自动清理历史残留。

### Q2. 应用装好了但连接显示"未工作"，设备也连不上

按顺序检查：

1. **系统设置 → 运行状态 → 立即检查**，确认「加密网络支持」显示为已开启
2. NAS 上执行 `ip link show wg0` 确认网卡已创建；`lsmod | grep wireguard` 确认内核模块可用
3. 确认路由器的 **UDP 端口转发**已指向 NAS 的局域网地址
4. 到 **系统设置 → 接入设置** 确认「对外访问地址」填的是外网可访问的域名或公网 IP
5. 重新生成设备二维码（配置里写的是生成时的地址）

### Q3. 设备显示在线但访问不了家里其他设备

「设备上网方式」选成了「只访问家里设备」时，只有**家里内网网段**的流量会走隧道。请到设备编辑页确认「设备上网方式」，或确认 NAS 所在网段被正确识别（可查看二维码里的「允许通行」范围）。

### Q4. 重启 NAS 后配置还在吗？

在。agent 启动时会先做一次网络自检修复，再执行全量收敛，自动重建全部连接与设备。这也是本项目相对手工 `wg-quick` 配置的核心优势。

### Q5. 能导入我原来手工写的 `wg0.conf` 吗？

可以。**我的连接 → 导入已有配置**，直接粘贴 `wg-quick` 格式内容，系统会识别其中的连接与设备；导入时如果该连接已存在，会拒绝覆盖以免影响正在使用的配置。

### Q6. 卸载会丢配置吗？

不会。卸载默认保留 `@appdata/fn-wireguard`（数据库与备份），重新安装后自动恢复。但会清理本应用创建的内核网卡与路由，不会给系统留下痕迹。
